# デザインピラー（ゲームの柱）

バランス調整やプレイテストの感想で迷ったときは、必ずここに立ち返る。柱を壊す変更は、どれだけ要望が多くても採用しない。（柱1と柱2は、2026-10-22 に開拓と糖度の版（`docs/PLAN-pioneer.md`）に合わせて書き直した）ただし要望の裏にある不満には、別の手段で応える。

1. **読みが当たる快感**: 町の糖度の流れ（食卓の偏り、ラッシュとクラッシュ、ライバルの動き）から、着いたときの町の姿を読み、運び、当てる。判断の余地がない仕組み（いつも同じ答えになる最適解）は柱を壊す。
2. **町を育てる手応え**: 自分の交易で町の「糖度」が上がり、町が育ち、新しい需要が生まれる。自分で開いた交易所が、集落・町・都市へ育っていく。
3. **甘い誘惑とその代償**: 甘味は短期の熱狂（シュガーラッシュ）を生むが、やりすぎると反動（シュガークラッシュ）が来る。安定した成長と一時の大儲けの間で、常に選択を迫る。
4. **ドーパミンが出る手触り**: すべての行動に、即時で、気持ちよく、ときどき予想を上回る見返りがある。
5. **作業は自動化で卒業させる**: 同じ操作の繰り返しが10回を超えるようなら、それは自動化の手段を渡す合図。卒業した先には、次の判断が待っていること。

## 感想の振り分けルール
1. 感想を **バグ / 分かりにくさ / バランス / 好みの問題 / 柱と衝突するもの** に分ける。
2. 腕前によって読み方を変える。
   - 下手な人が詰まった → まず分かりにくさを直す。難易度を下げるのは最後の手段。
   - 上手い人が必勝法を見つけた → 必ず潰す。
   - そこそこの人が退屈した → テンポとミドルサイクルの報酬を見直す。
3. 複数のテスター、または数値の裏付けがある問題だけを直す。
4. 柱と衝突する要望は採用しない。その裏にある不満には別の手段で応える。
5. ルールより先に数値を触る。
6. すべて `docs/balance-log.md` に残す。
