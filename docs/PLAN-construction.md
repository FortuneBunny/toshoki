# 建設要素の追加計画（区画方式）

Trade Empires（2001）の「町を自分で作る」手触りを取り入れる。町と町の間は今の路線図（町＝点、道＝線）のまま、**町の中に本格的なマス目（区画）を持たせ**、そこに建物を置く。原作の全面マス目化に近い遊びを、交易の中心（相場・商人・定期便）と調整済みのバランスを壊さずに実現する。

- 作成日: 2026-10-20
- 前提: 本編（`docs/PLAN.md`）は完成・公開済み。全員テスト3回で調整済み。

## 0. 方針
| | 路線図（今のまま） | 区画（新しく作る） |
|---|---|---|
| 範囲 | 町と町の間 | 町の中 |
| 単位 | 町（点）と道（線） | 12×12 のマス目 |
| プレイヤーがすること | 運ぶ、定期便、道を敷く | 建物を置く、市場の圏を広げる |
| 中身 | 相場、移動、砂漠、季節風、盗賊 | 生産、住居、労働力、需要施設 |

**柱との関係**
- 柱2（町を育てる手応え）: 町の成長が数字ではなく、区画に家が建っていく形で見える。
- 柱1（判断）: 限られたマスに「畑を置くか、住居の場所を残すか」という判断が生まれる。
- 柱5（自動化の先の判断）: 定期便を組んだあとに、町を設計するという次の層がある。全員テストの「待つだけ」（1〜3回目すべて）への根本的な答え。

**原作の反省を踏まえて避けること**
- 地形を自由に歩く経路探索はしない。移動は今の路線図だけ。区画の中は「置くだけ」で、商人は区画の中を歩かない。
- 1つずつの施設の細かい管理を強いない。生産施設は置けば勝手に動き、住居は勝手に建つ。

## 1. 区画のルール
### マス目と地形
- 町ごとに 12×12 の区画。斜め見下ろし（アイソメトリック）で描く。
- 地形: 平地、肥えた土地、砂地、水辺（海・川）、丘。
- 資源のマス: サトウキビ畑に向く湿地、ぶどうに向く斜面、ヤシの泉、塩田、鉱脈、茶畑の斜面、桑畑など。
- 生産施設の多くは、対応する資源のマスにしか置けない（どこに町を作るかが意味を持つ）。

### 市場の圏
- 区画の中心に市場がある。市場の圏（半径）の中にだけ建物を置ける。
- 圏は町の段階で広がる（集落 3、村 4、町 5、都市 6、大都市 7）。投資で「市場を拡張」して1段広げることもできる（高価）。

### 建物
| 種類 | 例 | 置く人 | はたらき |
|---|---|---|---|
| 生産（町のもの） | 麦畑、なつめやしの林、塩田、鉱山、養蜂場、茶畑、桑畑と絹織り | プレイヤーが投資して置く（最初からあるものもある） | 町の市場に品を出す（今の「特産」の代わり）。働き手が必要 |
| 工房（自分のもの） | 製糖所、菓子工房、醸造所、麦芽小屋 | プレイヤー | 今と同じ。倉庫へ入る |
| 需要施設 | 茶館、寺院、学問所、宮殿 | プレイヤー | その町に新しい需要を生む。品が届いていると成長が加速 |
| 住居 | 家（段階で見た目が変わる） | **自動** | 空き地に建つ。人口の上限になる |
| 拠点 | 隊商宿、倉、港 | プレイヤー | 隊商宿: 砂漠の食料を安く補給。倉: 倉庫の容量。港: 船の購入（港町のみ） |

### 人口・住居・労働力
- **住居**: 糖度が「安定」以上で、圏の中に空き地があると、少しずつ自動で建つ。糖度が低いと空き家になり、やがて取り壊される。
- **人口の上限**: 住居1軒あたりの人数（町の段階で増える）× 軒数。上限に達すると、糖度が高くても人口は伸びない。空き地を残すか、建物で埋めるかが判断になる。
- **労働力**: 生産施設には働き手が要る（例: 畑 30人、鉱山 50人）。町の人口の6割が働き手。足りなければ生産量が比例して落ちる。町が育つと生産も増える、という原作の循環。

### 町の生産は「置いた建物」から生まれる
- 今の `produces`（町ごとの固定の生産量）は、最初から区画に置かれている生産施設に置き換える。**開始時の合計はいまと同じ**にして、調整済みのバランスを保つ。
- プレイヤーが畑や鉱山を足すと、その町の供給が増え、相場が下がる（安く仕入れられる）。代わりに労働力と空き地を使う。

## 2. 交易所（新しい町を開く）と道を敷く
- **交易所**: 地図上の候補地（シナリオに2〜4か所）に交易所を開くと、小さな区画が生まれる（集落、市場の圏3）。候補地ごとに地形と資源が違う。隣の町との間に小道が1本できる。
- **道を敷く**: 2つの町を結ぶ小道を新しく作る。条件は次の4つ。
  - 直線距離が一定以内
  - 海を横切らない
  - 同じ2つの町の間にまだ道がない
  - シナリオごとの本数の上限以内
  
  既存の「街道に整備」と組み合わせられる。
- どちらも、今の路線図の上での操作（区画とは別）。

## 2.5 原作から取り入れる追加の要素
原作の資料を洗い直して見つかった、糖商記にまだない要素。区画とは独立しているので、区画の段階のあとに順に入れる。

### E1. 商人の才能
- 商人ごとに才能が1つある。雇うときは、候補（3人）から才能を見て選ぶ。
- 才能の例:
  | 才能 | 効果 |
  |---|---|
  | 健脚 | 移動 +15% |
  | 目利き | 売値 +4% |
  | 値切り上手 | 買値 -4% |
  | 砂漠の民 | 砂漠で食料を半分しか食べない。ロバでも砂漠で遅くならない |
  | 船乗り | 向かい風での遅れが半分 |
  | 腕っぷし | 護衛1人分の強さを自分で持つ |
  | 甘党 | 甘味を売るとき +6% |
- 最初からいる商人（ハサンなど）の才能は、シナリオで決めておく。
- 家訓とは重ねて効く（家訓は一族全体、才能は商人1人）。
- CLI: `hire` で候補3人の才能と費用を表示し、`hire <番号> confirm` で選ぶ。`merchants` に才能を表示する。

### E2. 技術の購入・独占・使用許可
- シナリオに「技術」の一覧を持たせる（例: ラクダの飼育、荷車、製糖、菓子づくり、季節風の航法、駅伝制、大型帆船）。
- 今は台本で日付ごとに自動で解放しているが、これを**お金で買う**形に変える。買うとすぐ使える。
  - 時代が進まないと買えない技術もある（日付の条件）。
  - 台本で自動で解放するものも、一部は残す。
- **独占**: ライバルのいるシナリオ（s7、s8）では、先に買った側が独占する。ライバルが先に買った技術は、相手に**使用料**を払うと使える（その代金は相手の資金になる）。逆に、自分が独占した技術の使用料をライバルから受け取れる。
- ライバルも資金があれば技術を買う（台本付き）。
- CLI: `tech`（一覧、値段、持ち主）、`tech buy <技術> confirm`、`tech license <技術> confirm`。ブラウザは上部に「技術」ボタン。

### E3. 音楽
- 地域（シナリオの舞台）ごとのテーマ曲を、WebAudio で合成した短いループで鳴らす。外部の音声ファイルは使わない。
  - 音階の例: 砂漠はヒジャーズ調、中国風は五音音階、海は穏やかな長調。
  - 拍は時間の速度に合わせて少し速くなる。
  - シュガーラッシュの間は華やかな変奏にする。
- 設定画面で音楽と効果音の音量を別々に変えられるようにする。
- CLI には関係しない。

### E4. 「結ぶ」「網を作る」型の目標
- 新しい目標の種類:
  - `link`: 町Aと町Bの間を、定期便が実際に一定回数往復した
  - `network`: 指定した町すべてに、定期便か交易所がつながっている
- 判定は、定期便の到着の記録で行う。
- 使う場所: s4（絹の道を結ぶ）、s8（大陸を結ぶ網）、フリープレイ。

### E5. シナリオを好きな順に遊べる設定
- 原作は好きな順に遊べた。糖商記は手引きの順番があるので、今の「前を達成すると次が開く」を基本にする。
- そのうえで、タイトル画面の設定に「全シナリオを解放」を足す（上手い人や再プレイ向け）。家訓の解放はシナリオの達成でのみ。

### E6. 住民の種類（要調査、保留）
- 原作の町の画面に、色の違う4種類の人の絵と人数がある（住民の階層か職業の区分らしい）。資料で確かめられていない。
- 区画の D2（住居と労働力）を作るときに、「住居の段階ごとに住民の種類が変わり、求める品も変わる」形で入れられるかを検討する。確かな資料が見つかるか、入れることでゲームが良くなると判断できたときだけ入れる。

## 3. 画面と CLI
### ブラウザ
- 地図の町をダブルクリック（または町パネルの「区画を見る」）で、区画の画面に切り替わる。
- 区画の画面:
  - 斜め見下ろしのマス目。左に建物の一覧（置けるものだけ明るく）、マスにカーソルを合わせると置けるか・効果の見込みを表示。
  - 住居が建つときは弾むように現れ、町の段階が上がると市場の圏が広がる演出。
  - 上部に人口、人口の上限、働き手（使用中 / 全体）、糖度。
- 素材（SVG、サブエージェントに `assets/STYLE.md` で依頼）:
  - 地形のマス（ひし形）
  - 生産施設、需要施設、拠点、住居（段階ごと）
  - 市場の圏の枠

### CLI（AI のプレイテストのため）
- `district <町>`: 区画を文字の格子で表示し、凡例を付ける。行と列に座標を振る。
- `place <建物> <列> <行> [confirm]`、`demolish <列> <行>`、`expand [confirm]`（市場の圏を広げる）。
- `buildable <町>`: 置ける建物と、置けるマスの候補を一覧で出す（座標を探す手間を減らす）。

## 4. 中身の変更
- **データ**: `src/data/district.js`（地形、資源、建物の定義）。シナリオに区画の生成の指定（地形の傾向と資源の位置）を足す。手で全マスを描かず、シードと指定から生成する。
- **新しいモジュール**: `src/core/district.js`
  - 区画の生成
  - 置ける判定
  - 住居の自動建設
  - 労働力の配分
  - 生産量の計算（今の `produce()` を置き換える）
- **city.js**:
  - 人口の上限を成長の計算に加える
  - 需要施設の需要と充足率を加える
- **セーブ**: 区画を保存する（12×12 の配列を町ごとに。圧縮した文字列で保存）。`SAVE_VERSION` を 2 に上げ、版1のセーブは読み込み時に区画を生成して移す。
- **経路探索・知識・ライバル・事件**: 町が途中で増えても動くようにする（交易所のため）。

## 5. 段階
| 段階 | 中身 | 完了の目安 |
|---|---|---|
| D0 土台 | 区画のデータと生成、既存の `produces` を最初の建物に置き換える（数値は同じ） | 全シナリオのボット結果が、今とほぼ同じ |
| D1 区画の画面 | ブラウザの区画の画面、CLI の `district` / `place`、置ける判定 | 建物を置いて、生産が増えるのが見える |
| D2 住居と労働力 | 住居の自動建設、人口の上限、労働力 | 「畑か住居か」の判断が生まれる。放置で目標に届かない |
| D3 需要施設 | 茶館・寺院・学問所・宮殿 | 売り先を作れる。成長が品の到着しだいで動く |
| D4 交易所 | 候補地、新しい区画の生成、町の追加 | 新しい町を開いて育てられる |
| D5 道を敷く | 道の追加と条件 | 自分でルートを設計できる |
| D6 統合 | シナリオとフリープレイへの区画・交易所・道の組み込み、手引き | 全シナリオで新しい要素が使える |
| E1 商人の才能 | 才能の定義、雇用の候補、効果 | 雇うときに選ぶ判断が生まれる |
| E2 技術 | 技術の一覧、購入、独占と使用料、ライバルの購入 | 台本の解放をお金の判断に置き換える |
| E3 音楽 | 地域ごとのテーマ曲（WebAudio）、音量の設定 | 地域ごとに曲が変わる |
| E4 目標の型 | `link`、`network` | s4、s8、フリープレイに組み込む |
| E5 全シナリオ解放 | タイトル画面の設定 | 好きな順に遊べる |
| F 調整 | 全員テスト4回目、調整、公開 | 下の完了の定義を満たす |

各段階の後に、単体テスト・ボットの回帰・ブラウザの自己テスト・Claude だけの小テストを行う。全員テストは D2 の後（中身のルールが大きく変わるため）と、F（すべて入れ終えたとき）に行う。E6（住民の種類）は D2 の検討事項として扱う。

## 6. シナリオへの組み込み
- **ギミック学習**: 新しい要素は、初めて出るシナリオで手引き付きで触らせる。
  - s1: 区画を見るだけ（家が建つのを見せる）
  - s2: 畑を1つ置く
  - s3: 工房を区画に置く
  - s4: 交易所と道
  - s5: 需要施設（寺院・茶館とラッシュ）
- s6〜s8 とフリープレイ: すべて使える。
- 目標は今のものを基本に残す。区画が入ったことで達成が早くなりすぎるなら、目標の数値を上げる。

## 7. 危険と対策
| 危険 | 対策 |
|---|---|
| 交易の中心が薄まり、建設の作業が増える | 区画は「置くだけ」。住居と生産は自動。手引きで1つずつ出す。全員テストで「待つだけ」と「作業が多い」の両方を見る |
| 調整済みのバランスが崩れる | D0 で開始時の生産を今と同じにする。段階ごとにボットで達成日数を比べる（2割以上縮むなら弱める） |
| CLI が遊びにくくなり、AI のプレイテストが高くつく | `buildable` で座標の候補を出す。文字の格子は凡例付きで短く |
| 描画が重くなる | 区画の画面は町を開いたときだけ描く。地図の画面は今の路線図のまま |
| 古いセーブが読めない | 版2と移行関数。版1のセーブで読み込みテスト |
| 作業量が大きい | D0〜D2 で一度区切って全員テスト。手応えがなければ、D3 以降は区画なし（今の町パネル）でも入れられるように作る |

## 8. 完了の定義
- 区画・需要施設・交易所・道を敷く・商人の才能・技術の購入・新しい目標の型・全シナリオ解放が、ブラウザ版と CLI 版の両方で使える（音楽はブラウザ版のみ）。
- 単体テスト・ブラウザの自己テストが通る。版1のセーブが読める。
- 全シナリオのボット回帰で、放置では達成できず、既存の目標が大きく簡単になっていない。
- 全員テスト4回目で、建設が「楽しい判断」と評価され、「作業が多い」が主な不満にならない。必勝法の報告がない。
- `docs/balance-log.md`、`playtests/round-4.md`、README を更新し、公開ページに反映する。
