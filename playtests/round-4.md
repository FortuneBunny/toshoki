## 区画の評価
- **好評**: Opus は「今回いちばん効いた新要素」、Sonnet は「荒野の中で町が育っていく感じが良い」、Luna は「家が自動で増えるのは見ていて面白い」。`buildable` で置ける座標の候補が出るのは全員に好評。
- **必勝法（柱2を壊す）**: Sol と Opus が別々に気づいた。目標の町の区画に、その町に足りない食べ物（水田、ぶどう園、なつめやしの林、キビ畑）を並べると、交易なしで食卓がそろって町が育つ。Sol は s5 を57日でS。
- **大都市では足しにならない**（Sonnet）: 1施設の産出が小さく、人口6000の町の需要の前では主役は荷車の定期便。

## 対応
| 指摘 | 対応 |
|---|---|
| 区画で食卓をそろえる必勝法 | 食べ物と甘味の施設は、その町が**元から作っている品の増産だけ**に限定。町にない資源マスは、食べ物以外の品だけをまれに置く。生産施設は**建設10日・維持費1銀/日** |
| 大口注文の「産地」が、地元でほぼ消費される町を指していた | 地元の消費より多く作る町だけを「仕入れられそうな町」として出す |
| 定期便の見送りで、値段の比較と表示の丸めが食い違う | 小数2桁で表示 |
| 「読み的中 +265」と売却利益 +105 の違いが分からない | 「出発時に知っていた相場との差」と明記 |

### 全面マス目方式で引き継ぐもの（G2 以降で対応）
- `place` / `expand` で、今その町にいる商人を自動で選ぶ。使えない `expand` は `buildable` に出さない。
- 定期便の1往復目が空荷になる、設定し直すと最初の停泊地へ空荷で戻る。
- 定期便の商人が止まった理由を `status` と `order list` に出す。
- ラッシュの予兆（甘味の摂取 n/75 の意味、あと何個で起きるか）を `status` にも出す。
- 工房の自動仕入れが止まったときの警告をもっと目立たせる。同じ警告の繰り返しを1行にまとめる。
- 砂漠で道中に食料が何個減るかの見込みを出発前に出す。
- シナリオの最初に、区画に施設を置けることと家が増えることを短く案内する。

## 採用しなかったこと
- 「区画の施設をもっと強く」（Sonnet）: 大都市を区画の生産で養えるようにすると、交易で町を育てる柱2が崩れる。区画は産地への投資と町の姿づくりの役割にとどめる。
- 「trade に確認を挟む」（Haiku）: CLI は `quote` と `trade` で分けてあり、ブラウザ版は確定ボタン方式。確認を挟むと操作が重くなるので見送り。
