# テスト 7回目（住居の求める品 E6 の確認。Claude のみ）

- 日付: 2026-10-20
- 対象: 住居が地域の品を求め、1つ欠けまでそろえないと家が建たない版。シード71、1シナリオあたり最大160コマンド。
- 割り振り: Opus（s8）、Sonnet（s6, s4）、Haiku（s2, s5。実際は s2〜s5 の4本を遊んだ）

|---|---|---|---|---|

## 見つかったバグ（すべて対応）
| 指摘 | 対応 |
|---|---|
| **区画が家で埋まると、琥珀京が大都市（8000）の手前の7590人で止まる**（Opus） | 家1軒に住める人数が今の段階で決まっていた。次の段階に近づくほど家が大きくなるようにした。目標のある町は、どれも区画に収まることを確かめた |
| `order list` が `load:品*数` を含むと落ちる（Haiku） | 直した。画面の定期便の設定も対応 |
| 定期便を設定し直すと、積荷を持ったまま最初の停泊地へ戻る（Sonnet。4回目からの持ち越し） | 今の行き先、積荷を売る停泊地、一番近い停泊地の順に選んで始める |

## 分かりにくさ（対応したもの）
- 交易所や小さな町が買い取らない品に気づかない（Opus） → 定期便を設定したときに「○○は今は△△を買い取らない」と警告。
- 寄進すると資産の目標を割り、達成が取り消される（Haiku） → 寄進の前に「資産が目標を割る」と警告（画面と CLI）。
- 「C」ランクがルールにない（Haiku） → ルールの説明に追記。
- 最初の助言で、行き先も作っている品を勧めた（Opus） → 行き先が多く作っている品は勧めない。

## バランス
- s5 のラッシュに、そこそこの役（6回目）と下手な役（7回目）が届かない。ラッシュの甘味の条件を「必要量の75%以上」から「70%以上」に下げた。表示もこの値に合わせて変わる。
- 住居の求める品は、上手い役と、そこそこの役が「足りない品を作る施設を置く」「運ぶ」で応えていた（Opus は養蜂場・茶園・絹織りの家を置いた）。上限が理不尽に感じられたのは、上のバグが原因だった。

## 採用しなかったこと
- 「寄進を資産に数える」（Haiku）: 寄進は町への投資で、取り戻せない。資産目標との引き換えは判断の一部として残し、警告で知らせる。
