# テスト 20回目（売り場の交代の敵対的評価。Sol・Opus）

- 日付: 2026-10-23
- 対象: 19回目の相談の「最初の一歩」を入れた s3（予告された売り場の交代と、臨時の便）。
- やり方:
  - 仕様とソースを読ませ、CLI と、ゲームの操作だけを使うスクリプトで遊ばせた。
  - いちばん大事な問いは「予告を読まない固定の手で S に届くか」。
  - 固定の手は、予定の列も予告も読まない決まりにした。

## 結果
- **2人とも、予告を読まない固定の手で S に届いた**。開発者のボットは固定の手の土台が弱く、比べ方が偏っていた。
  - Sol: 白糖を待つ数を16個から12個にするだけで、2対1の固定が S 15/30。
  - Opus: 2つの手を合わせた固定の便が、S（155日）に9割届いた。
    - 糖蜜町へ小道を1本敷く。
    - 2つの売り先を1便で回り、最低売値35で売る。安い町では持ち越して、もう一方の町で売れる。
    - 予定の列を空にした場合と比べると、交代はこの便に約8%の税をかけるだけだった。
- 読む手はどちらでも速かった。
  - Opus の読む手: 中央117日。
  - Opus が CLI で読んで遊んだシード7: 117日 S（同じシードの固定の手は144日）。
- 予告から臨時の便を組むまでの手順は、2人とも「分かる」「面倒ではない」と評価した。
  - Opus: 判断は30〜50日に1回、1回あたり2〜3コマンド。
  - Sol: 同じ長い停泊地を、商人ごとに打ち直すのが手間だった。

## 見つかって直したもの
- **固定の手に効きが足りない**（2人とも）:
  - 低迷を強めた（需要3割・値7割 → 15%・50%）。
  - 出来事の期間を延ばし（30日 → 35日）、休みを縮めた（12〜22日 → 4〜12日）。
  - 隊商市の値は基準どおりにした（1.1倍 → 1.0倍）。隊商市の町をいつも通る固定の便が、隊商市の高値を拾っていたため。
  - S を、道と最低売値を使う固定の便と読む手の間に引き直した（155日 → 126日）。
- **ボットの土台**（Opus）: Opus の固定の手と、それに予告を読む手を重ねたものを `tools/sim-shifts.js` に入れた。比べたのは次の4つ。
  - 2町を回る便（loop35）
  - 1人だけ蜜蜂の丘も毎回通る便（hill35）
  - 予告を読む手（readL）
  - 始まってから回す手（reactL）
- **未来の予約を足すと、今回っている臨時の便まで消えた**（Sol）: 先に始まる予約は、新しい予約の始まりで終わりにする。今の便はそこまで続く。
- **市が閉じる日に着く便の予約を勧めた。間に合わないときも予約を出した**（2人とも）:
  - 期間の終わりに2日の余裕をみる。
  - 間に合わないときは「着けない」と出し、CLI の `--shift` では予約しない。
  - 「町を出る期間」と「市で売れる期間」を分けて書いた。
- **「1日に約5個まで」は買取の上限ではなかった**（Sol）: 「毎日約5個ずつ売れていく。まとめて売ると値が下がる」と書いた。
- **同じ停泊地を商人ごとに打ち直していた**（Sol）: `order alt --shift <番号>` で停泊地を省くと、いつもの便の安くなる町を隊商市の町に替えた便を予約する。
- **隊商市が閉じたあとの在庫を買い戻して売り直すと、売った額に2回数えられた**（Opus）: 閉じた日に、隊商市の白糖の在庫をなくす。
- **セーブに先の予定が平文で入っていた**（Opus）: 予告ずみの分だけを書く。続きは、ロードのときに同じ乱数で作り直す。
- **工房が市場から白糖を自動で買った額が、目標「売った額」から引かれなかった**（Opus）: 引く。
- 細かいもの:
  - `shifts` の「約20日前」を「約26日前」に直した。
  - 予約ずみの便に付いていた ⚠ を外した。
